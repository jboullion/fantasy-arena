# Unity gameplay migration — verification

Validated 2026-09-08 with Unity 6000.6.0f1. This advances the foundation described in `Unity Foundation — Verification.md`; it does not complete every item in the release brief.

## Delivered

- Plain C# combat for four classes, melee windups, projectiles, contact damage, knockback, armor and fire/lightning/ice/poison effects.
- Seeded terrain and collision, enemy variants and boss actions, six-round progression, rotating weapon offers, purchases, rewards and retry retention.
- Imported roster, weapons and terrain with procedural character poses and attack warnings.
- Class selection, online ready checks, local player selection for purchases and current-run statistics.
- Versioned run reports with atomic replacement, backup, per-run updates and retention of the latest 20 reports. Saved-history UI and persistent settings remain pending.
- Separate validation/build copy, allowing the main Unity editor to stay open. Existing source editor settings are preserved.

Combat fixtures are generated by `scripts/unity-parity.ts` from the browser implementation and consumed by `Editor/ArenaParity.cs`. They cover four classes across five weapon states plus knockback, contact, armor, poison, dodging and ice slowing. These are selected scenario comparisons, not proof of identical full-run behavior or balance. Six-round settlement is a core test; executable smoke tests complete round one.

## Remaining work

Manual class/shop and four-player UI playtesting, controller focus/assignment polish, audio, cosmetic ragdolls, particles and final social scenes/art remain. Current statistics presentation is provisional, especially for large parties. Character/equipment combinations have not all received visual inspection. Boss behavior is implemented, but full boss encounter feel and every special-action edge case need playtesting.

Real controllers, two physical PCs, internet multiplayer and a 200-enemy performance/bandwidth benchmark remain unverified. Steam services are not integrated. Protocol 2 requires both peers to use the updated build. Host loss ends the session; seamless host migration and the proposed guest reconnection window remain deferred. Network snapshots are still JSON and have no production bandwidth claim.

Offline play does not initialize the game's network manager; these tests did not disable OS networking. Computer Use capture was unavailable, so the visual check used the explicit Unity render request, not manual desktop UI automation.
